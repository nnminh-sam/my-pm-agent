Email + password users, stateless HS256 JWT sessions. No new npm deps: `node:crypto` only (Next 16 proxy runs on Node.js).

## Modules (`src/lib/auth/`; `auth.ts` → `auth/index.ts`)
- `password.ts` (PMA-M1-T2): scrypt N=2^17 r=8 p=1, keylen 64, 16-byte salt, encoded `scrypt$<log2N>$<r>$<p>$<salt>$<hash>` (b64url); verify via timingSafeEqual, malformed → false. Policy: 10–256 chars, ≠ email.
- `jwt.ts` (PMA-M1-T3): header exactly HS256/JWT; claims sub, email, iat, exp, iss="my_pm", auth_time. Reject alg≠HS256/none, bad sig, expired, wrong iss, malformed. `JWT_SECRET` ≥ 32 chars.
- `users.ts` (PMA-M1-T5/6): signUp / logIn service shared by server actions and JSON routes.
- `index.ts` (PMA-M1-T8): modes, cookie, issueSession, authenticate().

## Session policy
- 2 h access token in httpOnly `pm_session` cookie (sameSite lax). Proxy re-signs when < 1 h left; absolute cap 30 days from auth_time. Logout clears the cookie (no refresh tokens).

## User model (PMA-M1-T4)
- `UserMeta` (id `U-n`, email normalized lowercase, password_hash, created). `migrations/002_users.sql` (unique email). File backend `users/U-n.md`. Repository: getUser, findUserByEmail, countUsers, insertUser → null on duplicate. Not part of import/export.

## Sign-up policy
- Single-user app without per-user data scoping → sign-up open only while no users exist, or for emails in `PM_SIGNUP_EMAILS`. Duplicate email → 409.

## Login
- Generic "Invalid email or password."; dummy-hash verify for unknown emails (timing).

## Modes
- `JWT_SECRET` set → jwt; unset → open locally / locked on Vercel. `/api/*` also accepts `Bearer <PM_SECRET>` until PMA-M4 API keys land. PM_SECRET web login form removed.

## Routes
- Server actions signUp/login/logout; JSON `POST /api/auth/{signup,login,logout}` (400/401/403/409). Proxy public: /login, /signup, /api/auth/*. Pages /login, /signup, logout button + signed-in email.

## Out of scope
- Rate limiting, refresh tokens, password reset, email verification.
