## Goal
Authenticate AI agents (MCP clients) against `/api/mcp` with a long-lived API key, separate from the user-facing JWT login in [[F-1]], so agents can be issued, rotated, and revoked their own credentials independently of a human session.

## Scope
- Generate an API key (random, high-entropy token) tied to this app; store only a hash of it, never the raw value.
- `/api/mcp` accepts `Authorization: Bearer <key>` and validates it against the stored hash before allowing tool calls.
- Key management: issue a new key, list active keys (masked), revoke a key.
- Invalid/missing/revoked key on `/api/mcp` returns 401 with a clear error (matching the shape MCP clients already surface).
- Document how to configure the key in an MCP client's `headers.Authorization`.

## Out of scope
- Per-key scopes/permissions (all keys get full MCP access for now).
- Multi-user key ownership (single-user app; keys aren't attributed to individual accounts).
- OAuth flows for MCP (explicitly bypassed — this is a static bearer key, matching the "OAuth fallback is disabled when headers.Authorization is set" behavior clients already expect).

## Acceptance criteria
- A generated key authenticates successfully against `/api/mcp`; an unknown, malformed, or revoked key gets 401.
- Revoking a key immediately blocks further use of it.
- No raw key is ever persisted or logged after issuance (issuance is the only time it's shown in full).
- Tests cover valid key, missing header, malformed header, unknown key, and revoked key.
