## Goal
Integrate authentication for normal users via email + password, using JWT for sessions.

## Scope
- Sign up with email + password (email format validation, minimum password strength).
- Passwords hashed with a slow hash (bcrypt/argon2); never stored or logged in plain text.
- Log in with email + password → issue a signed JWT (short-lived access token).
- Protected routes/API verify the JWT (signature, expiry) and reject missing/invalid tokens with 401.
- Log out (client discards token; refresh token revoked if used).
- JWT secret loaded from environment config, not committed.

## Out of scope
- OAuth / social login, SSO.
- Admin/role management beyond "normal user".
- MFA, magic links.

## Acceptance criteria
- A new user can register and then log in with the same credentials.
- Wrong email or password returns a generic error (no user enumeration).
- Duplicate email registration is rejected.
- Requests with a valid JWT reach protected endpoints; expired/tampered tokens get 401.
- Tests cover register, login, token verification and failure cases.
